# LoanDesk API v1

Base URL while running locally: `http://127.0.0.1:8000/api/v1`

Interactive API schema: `/docs` (OpenAPI/Swagger). All application and administrator APIs use bearer access tokens. On a live deployment the site and API must be served behind HTTPS.

## Customer authentication

### `POST /auth/request-otp`

```json
{ "phone": "+923001234567" }
```

Response:

```json
{ "challenge_id": "<uuid>", "expires_in": 300, "message": "If the number can receive messages, a verification code has been sent." }
```

The OTP is generated by the server. It is never returned in this response, never displayed in the administrator portal, and never stored in raw form. In development-only console mode, the test SMS is printed to the backend terminal. Production must use a real configured SMS provider.

### `POST /auth/verify-otp`

```json
{ "challenge_id": "<uuid-from-request>", "otp": "123456" }
```

Returns `{ "access_token": "...", "token_type": "bearer", "expires_in": 3600 }` for a valid, unexpired, single-use code. Five failed attempts are allowed by default; the challenge then expires. Wrong attempts are audited by time, masked phone, result and request metadata, never by the code itself.

### `GET /me`
Returns the current user and latest application summary.

### `POST /application/kyc`
`multipart/form-data` with `pan_number`, `consent=true`, `selfie` (image), and `pan_image` (image). Each upload is limited to 5 MB, decoded/re-encoded to remove EXIF metadata, encrypted at rest, and accessible only to an authorised administrator. Submitting a selfie is not the same as biometric liveness detection: this build marks liveness as `manual_review_required` until an approved provider integration is configured.

### `GET /application/me`
Returns the current user's application status and masked account information.

### `POST /application/account`

```json
{
  "account_holder": "Example Customer",
  "bank_name": "Example Bank",
  "account_number": "000123456789",
  "routing_code": "OPTIONAL"
}
```

Account and identity strings are encrypted at rest.

## Administrator authentication and review

### `POST /admin/login`
`{ "username": "admin", "password": "..." }`

Returns a short-lived administrator bearer token. Local first-run credentials are written to `data/admin-initial-credentials.txt` if `ADMIN_PASSWORD` is not set. Use a unique password in `.env` for any deployment.

### `GET /admin/overview`
Summary statistics.

### `GET /admin/applications?status=under_review&limit=100`
Application queue. Sensitive identifiers are masked by default.

### `GET /admin/applications/{application_id}`
Application metadata and masked account details.

### `POST /admin/applications/{application_id}/reveal`
Requires a `purpose` of at least five characters. Returns the full PAN/card identifier and full account details and records a sensitive-data access event.

### `GET /admin/documents/{application_id}/selfie` and `/pan`
Streams the selected identity image to an authenticated administrator without exposing the private storage path.

### `PATCH /admin/applications/{application_id}`

```json
{
  "status": "under_review",
  "review_note": "Please confirm the account holder name.",
  "offer_amount": 50000
}
```

Allowed states: `under_review`, `needs_information`, `approved`, `rejected`. The status is a manual record; it does not disburse a loan.

### `PATCH /admin/settings/offer`
`{ "offer_amount": 50000 }` changes the public maximum/ceiling shown to customers. It is not a guarantee of approval.

### CSV exports
- `GET /admin/export/applications.csv` — masked identifiers only.
- `GET /admin/export/otp-audit.csv` — request and verification outcomes only; never contains OTP values.

## SMS configuration

For local tests use `SMS_PROVIDER=console`. The one-time code is written to the server terminal only and is not returned by an endpoint or stored in the audit log.

For Twilio, set `SMS_PROVIDER=twilio`, `SMS_TWILIO_ACCOUNT_SID`, `SMS_TWILIO_AUTH_TOKEN`, and `SMS_TWILIO_FROM` on the server. Use provider-approved templates and sender configuration for the destination country. Credentials must never be added to the Android APK or browser JavaScript.

## Error responses

Errors use standard JSON such as `{ "detail": "The code is incorrect or expired." }`. Typical statuses are 400 (invalid/expired code), 401 (missing/expired token), 403 (wrong role), 409 (an active request already exists), 413 (image too large), 422 (invalid fields), 429 (rate limit), and 503 (SMS provider failure).
